Contributing and attribution

Issues and pull requests are welcome at AoharuCat/Closure. For larger features, first discuss the use case, benefit, and boundaries in an Issue.

Make a reviewable PR

Section titled “Make a reviewable PR”
  1. Fork the public repository and branch from main.
  2. Keep each PR focused on one problem and follow the module’s style and boundaries.
  3. Verify changed behavior and run root typecheck, lint, and test.
  4. Include actual images for interface changes and name the tested platforms and remaining gaps.
  5. Update relevant documentation or change notes, and open a PR to public main describing the problem, result, and evidence.

Reuse theme tokens for UI colors and scales instead of scattering hardcoded values through features. Keep cross-package types and validation contracts aligned. The contribution guide is the authoritative contributor reference.

Report problems

Section titled “Report problems”

Include reproduction steps, expected and actual behavior, OS, and app version. Remove API keys, account details, and private drafts from diagnostics or logs. Prefer a minimal example over publishing an entire personal writing project.

Report vulnerabilities privately through the route in SECURITY.md, rather than disclosing exploitable details in a public Issue.

Licenses and attribution

Section titled “Licenses and attribution”

Closure builds on OrisonSpace and incorporates other components. Before contributing or redistributing, read the current LICENSE, NOTICE, and relevant component licenses. Preserve existing copyright and source notices; the original files govern their respective terms.
