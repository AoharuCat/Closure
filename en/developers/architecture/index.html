Architecture and directories

Closure is an Electron desktop app. React renders the interface, the main process owns local capabilities, orchestration runs as an embedded library, and project files live in a user-selected directory.

Code map

Section titled “Code map”
Directory Responsibility
apps/desktop/client/shell Electron main/preload, local capabilities, and model gateway
apps/desktop/client/ui React editor, workspace, structure page, and state
apps/desktop/agent Embedded orchestration, tools, and writing workflows
apps/desktop/local-bff Local project files and data access
packages/shared-contracts Cross-process types and validation contracts
packages/model-protocols Model protocol adapters
packages/story-sync Shared story-synchronization logic

Manifest names still use @orison/*. Use those real names in filtered commands; a package name different from the product branding is expected.

Data and runtime boundaries

Section titled “Data and runtime boundaries”

Chapter Markdown, outlines, and settings are local project content; indexes support retrieval. The UI requests main-process capabilities through preload/IPC. Orchestration uses injected model and tool capabilities. When changing a cross-layer behavior, inspect both ends and the shared contract. Keep Electron and filesystem operations out of rendering components.

“Local-first” describes storage and runtime organization. It does not mean an online model never receives task context. Do not turn a storage description into an unsupported guarantee about external providers.
