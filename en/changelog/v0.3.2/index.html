v0.3.2 · A more reliable CLI integration

2026-09-19 (UTC)Original GitHub release ↗All releases

Historical release notes: capabilities and limitations describe this version at publication. English text from the original release.

This release is the fourth dogfood round's fix batch: it takes the Antigravity CLI integration from "it connects" to "it holds up" — adding the proper in-project search and directory-listing path, turning the empty-turn failures caused by denied built-in tool calls into something visible and recoverable, and fixing a set of places that failed silently or blamed the wrong cause.

New Features

  • Model settings: Antigravity CLI credential probe — connectivity is checked automatically at startup, plus a manual "Test connection"; a dead credential shows a persistent status row and a notice
  • Model settings: Antigravity CLI accepts a custom agy executable path (leave blank to auto-detect the default install location)
  • Agent page: Antigravity CLI models carry a form badge (CLI · 无工具调用)
  • Antigravity CLI: in-project search and directory listing are now available — the model can answer "where is X in this project" and "what is in this directory" directly, instead of falling back to built-in tools that get denied
  • Antigravity CLI: leaving the writing toolset now produces a visible notice (naming the tool it tried); when such a call empties the turn, the system injects a correction and continues the turn, recovering it
  • Settings: Closure text agent card — the plain-text lane mounts a writing-persona agent, toggleable, with file state and startup reconciliation
  • Diagnostics: Antigravity CLI log observation — the session's agent-loaded state is written to the app log

Fixed

  • Knowledge base: vector index dimension drift now self-heals — switching embedding models no longer leaves a permanent "vector search degraded" banner
  • Distillation: a "running" ledger row left by an interrupted run is reconciled at startup — the status strip no longer hangs forever
  • Antigravity CLI: an expired credential no longer ends as an "empty response"; it now reports a readable error with terminal re-login guidance
  • Antigravity CLI: fixed the misattributed error when a built-in tool call is denied
  • Antigravity CLI: fixed a path-validation defect that made the whole lane unusable in production
  • Antigravity CLI: fixed the misattributed error when authorization is denied — an authorization problem is no longer reported as "tool denied"
  • File tools: reading past the end of a file no longer silently returns nothing — it reports the total line count and the usable range; added a continuation signal (and made it visible to the model)
  • File tools: directory listing and search now validate paths as strictly as file reads — in-project symlinks can no longer reach content outside the project
  • Model settings: out-of-range parameter values now show a visible notice when rejected
  • Settings: the close-bridge notice shown while a session is active now states the real release condition
  • Branding: the runtime fallback prompt's persona is corrected from Orison to Closure

Known Issues

  • Antigravity CLI cannot dispatch the writing chain or the planner agents right now: it can only call a restricted tool subset, so tools such as the chapter-writing chain and planner dispatch are unreachable for it. In practice — asking the dialogue model to "write chapter one" makes it write the prose straight into the chat, without triggering the writing chain (the writing page timeline stays empty). This capability is under development and will land next release.
  • Antigravity CLI models may still attempt to call agy built-in tools; such calls are denied by headless permissions. The system injects a correction and retries once, but the turn may still fail.
