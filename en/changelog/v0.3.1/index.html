v0.3.1 · Build and startup checks across three platforms

2026-09-19 (UTC)Original GitHub release ↗All releases

Historical release notes: capabilities and limitations describe this version at publication. English translated for this site from the original Chinese notes.

Closure v0.3.1 brings the whole cross-platform path from packaging to running: CI checks the build, tests, and startup smoke on three platforms, alongside a batch of platform fixes.

Changes

  • Cross-platform support: Windows, macOS, and Linux are mechanically checked for build, tests, and startup smoke on every push; this does not establish full hands-on coverage.
  • One source of filesystem naming rules: manually entered project and file-tree names reject Windows reserved names, invalid characters, and excessive length. Generated chapter, export, image, and material names are sanitized automatically.
  • Native Linux file watching: external changes refresh automatically instead of requiring manual refresh.
  • Normalized file decoding: GBK Chinese text and CRLF files no longer become garbled or carry carriage returns into generation.
  • Data-loss fix: moving a file to an existing destination on macOS or Linux now fails explicitly instead of silently overwriting it.
  • macOS case handling: fixes rename and mention-ledger directory checks on the default case-insensitive filesystem.
  • agy integration: common installation paths are searched when a macOS or Linux graphical session has a limited PATH; Windows npm shims get specific guidance, and temporary session cleanup is hardened.
  • More packages: adds macOS ZIPs and Windows/Linux ARM64 builds.

Platform coverage

Platform Packages
Windows x64 / ARM64 Closure-Setup-0.3.1.exe (combined installer), Closure-portable-v0.3.1-win-x64.zip
macOS ARM64 / x64 DMG and ZIP
Linux x64 / ARM64 AppImage

Known limitations

  • macOS packages are unsigned. The release instructs users to open by right-clicking, or run xattr -cr /Applications/Closure.app after verifying the download. In-app automatic updates are unavailable until signing is implemented.
  • ARM64 artifacts have mechanical checks (CI and startup-smoke evidence), but have not been tested on physical hardware.

See the repository CHANGELOG.md for the complete changes.
