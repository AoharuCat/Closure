**Closure** 是一款开源、本地优先的 AI 小说创作 IDE，面向网文与长篇小说作者，把大纲、章节、人物与世界观资产卡整合到一个工作区。它以「用户主导创意、AI 执笔与自查」为原则，提供 AI 生成、续写、润色、审阅与可控修改；模型可接任意 OpenAI 兼容端点，也可经 Antigravity CLI 直连调用 Gemini 系列模型；所有创作数据保存在你自己的电脑上。Windows 优先，macOS / Linux 继承自上游架构。Closure 以 AGPL-3.0-or-later 许可证开源（源自 OrisonSpace 的代码保留 Apache-2.0）。

## 为什么做 Closure

**先说立场：创意写作，归根结底是人类的工作。**

输入一句话就让 AI 生成整篇小说，只会制造出垃圾——我们不做这种产品，也明确不服务想要这种产品的用户。

Closure 面向的是这样的人：**有灵感、有脑洞、有思考能力，但不一定有写作能力**。你想尝试写小说，却没有时间、没有精力，或者自认文笔不行——没关系，你出创意和判断，Closure 出笔力和工程。整个系统里，构思、取舍、拍板永远是你的；查漏、续笔、改稿、自审是它的。

做这个项目的起点，是两个观察：

1. **现有 AI 写作工具都在「先写后修」**。它们本质上是自回归生成加风格补丁：AI 先写出「像 AI 写的」文本，再用规则、词库、重写去修。没有一个真正建模过写作思维——作者构思故事时的信息差操控、情绪弧设计、角色欲望的演变、百万字的长程一致性。调研里 67% 的写作者从不使用 AI 写作工具，最集中的原因就是「AI 写的不像人写的，修起来比自写还累」。
2. **同人作者找不到趁手的工具**。写同人需要完整理解原作（世界观、主题、基调、人物形象连同社区共识），需要受控的偏离而非随机跑偏，需要「不 OOC」的动态把关——市面上没有工具原生支持这些。

Closure 的回答是：让 AI 像人类作者一样，先在结构化的叙事状态上**操控**（谁知道了什么、情绪走到哪了、欲望指向哪里），再落笔生成正文——而不是生成完再修。写作思维被工程化成系统的一部分，而不是事后补丁。

如果一切顺利，两三年后会有这样的画面：一位作者用 Closure 写出一部角色不崩、信息差精巧、情绪起伏有设计、百万字不散架的长篇或同人——而整个创作过程像导演一场 AI 协作，不是在修补泔水。

## 名字的由来

Closure（可露希尔）是《明日方舟》里的干员，罗德岛的工程系统负责人。

立项的时候，市面上找不到一个对同人创作真正友好的写作工具，而我们刚好就想写明日方舟的同人；那阵子又恰逢游戏七周年、可露希尔的卡池开了，于是顺水推舟，把她的名字给了这个项目。同人创作支持在[路线图](#路线图)上，我们会做回来。

## 核心理念

- **让 AI 像人类作者一样思考**——故事工程的理论根基是亚里士多德四因说（材料 × 形式 × 动力 → 目的）：设定是材料，结构是形式，角色欲望是动力，主题是目的。Closure 把这套写作思维逐层工程化。
- **AI 主笔，你做导演**——AI 负责执行你的创意：构建结构、生成正文、自查质量；你负责关键引导、注入灵感、最终裁决。每一处 AI 改动都可预览、可对比、可回退。
- **质量优先，诚实开源**——先保证质量，再用模型路由控制成本，不靠跳过审核或降级质量省钱。不推荐具体模型、不接商用检测器、无商业化，AGPL-3.0 完全开源。

## 功能亮点

### Closure 叠加层：叙事工程

在 OrisonSpace 的写作 IDE 基座之上，Closure 围绕「让 AI 像人类作者一样操控信息差、情绪与欲望」重建了生成管线：

- **多线叙事结构** — 用一张场景图统一管理故事骨架，多条故事线并行推进、互相咬合
- **结构工作台** — 一页总览全书的结构页：因果骨架与编排工作台两区联动，章节轴按卷分带、小地图支持长篇导航；情绪、节奏曲线可作为叠层开关盖上结构图（伏笔叠层规划中）；**同构锁步**——在任意区域选中一个元素，关联的卡片同步高亮，跨区追一条线索不用来回翻
- **信息差操控** — 记录每个角色知道什么、读者知道什么。审核能发现「角色说了不该知道的」「该揭的伏笔忘了揭」这类漏洞，而作者故意的隐瞒和延迟不会被误报
- **世界事件系统** — 每章写完，自动从正文提取五类变化（物理、认知、情绪、关系、势力），归并出随剧情推进的世界状态快照。关键在于账分两层：**事实真相**与**读者此刻所知**分开记录，两者的差距就是你的伏笔库存——该埋的没埋、该揭的没揭，系统看得见。后续章节动笔时，角色此刻知道什么、关系走到哪了，自动进入写手上下文
- **世界状态面板** — 侧边栏「世界」入口：以世界事件为主线的读面，总览 / 时点 / 主体三级缩放，写章推进时实时刷新——随时回看「世界此刻发生了什么」
- **情绪工程化闭环** — 每场戏先定好想要的情绪，写完自动检查情绪是否真的落了地，没落地就打回修
- **写章链** — 写一章的完整流程：对话下意图、导演核对设定、装配上下文、写手成稿、检查点停下等你过目、审核修订、落章后回来汇报。每一步都暂停等人，方向盘始终在你手里；写作页以一条全程时间线把思考、调查、产出、正文流逐段亮出，审批就地处理，终稿可直接手改、选中文字即让 AI 精修
- **双层编排架构** — 战略层是对话里的总指挥（你在环、随时改向），战术层是带显式契约的节点链（依赖不漏、工件流转不靠提示词隐性携带）；链段只把摘要带回对话，内部过程不占用你的上下文；检查点可暂停、可恢复、可改稿重跑
- **写手两阶段成稿** — 写手不是一口气生成：先自查上下文缺口，列出调查清单，资料员逐条核实后才开始动笔。上下文预算耗尽时按降级梯裁剪，故事骨架、全书目录、可查指针永远不裁
- **联网研究** — 写作前先查资料：多家搜索供应商可配（Tavily / Bocha / AnySearch，密钥只存本地）。资料员检索、导演核实——发现与既有设定矛盾会直接打回让你澄清，研究结果以卡片形式沉淀进工作台。写同人核对原作设定、写都市文查行业细节都用得上
- **对话传附件** — 对话框直接上传文档与图片：txt / docx / pdf 等自动解析为可读文本，图片交给视觉模型识别（识图进度实时可见），参考资料随手给
- **修订保义** — AI 的每一处改动都以词级对比展示，改了什么、有没有偏离原义，一眼可验
- **百万字不迷路** — 章摘要、完整性校验、提及台账，写到百万字依然记得谁在哪章说过什么
- **涟漪传播** — 改了第 3 章的设定？系统沿叙事依赖图正向追查，自动标出下游哪些章、哪些线索受影响、影响是什么类型——改设定的账不会漏记
- **去 AI 味** — 内嵌 [llmlint](https://github.com/notnotype/llmlint) 静态引擎，数百条规则纯本地扫描，零成本揪出「AI 腔」；配合 Lint 面板与修订闭环逐条清掉
- **风格卡** — 贴一段你心仪的小说，子代理把它分析成一张风格卡存进项目（含原文范例）；之后写手、精修、规划都会参考它。没有风格卡也一切照常
- **手艺知识库（craft KB）** — 内置写作方法论知识库：手艺条目、出处锚定、按主题归类，写手、导演、审核都能查证引用；种子内容随应用分发，你也可以自己扩充
- **材料库** — 把读过的小说、剧本、字幕批量导入项目（txt / docx / pdf / epub / srt / ass / vtt 等常见格式）：自动识别章节结构、建立全文索引，每份材料带质量标记与出处信息——写作与拆书共用这份语料
- **拆书引擎** — 选一本导入的书，按档位与维度跑拆解：事实设定（世界观 / 人物 / 势力）、读法、章评与细批、风格特征逐层产出，关键节点停下人工把关；风格分析导出为风格卡，写作经验蒸馏为手艺卡——别人写得好在哪里，拆开看清楚再学
- **双层审核** — 先跑免费的纯代码规则，零命中的稿子直接放行；有问题的才交给模型细审（一致性、叙事特征、承诺兑现、认知状态、情绪落地、设定契约六组）。纪律有二：**每条意见必须附原文引证**，说不出证据就不许说；**宁可误报不可漏报**，审核层永远不许「假通过」
- **模型分档路由** — 规划、正文写作、审核、研究、风格分析等各个环节，可以分别指定不同的模型与档位：最强的模型留给正文，便宜的模型跑杂活；每个环节的思考深度（推理力度）也能单独调节，成本花在刀刃上
- **Antigravity CLI 接入** — 除 OpenAI / Anthropic 兼容端点外的第三条模型通道：经 Google 官方 agy CLI 直连 Antigravity，调用 Gemini 系列模型——不经第三方中转（反代），密钥与请求数据不经他人之手，也没有中转站跑路、计量注水一类风险；订阅配额内的成本远低于按 token 计费的官方 API。配合工具桥，对话模型还能在一次性授权后调用 Closure 的写作工具（写章、查设定、资料检索）；间接调用的 ToS 灰区与账号风险，应用内配置处另有明示
- **用量面板** — 「用量」页为本机调用留账：token 与耗时按模型、按任务档位分解，估算费用、失败次数与首字延迟一目了然；记录按保留窗自动清理，只存本机
- **创作决策留档** — 重大创作选择像架构决策一样留档记录（为什么这么定、备选是什么），审核据此判断后续章节有没有违背你定下的承诺

### 基座能力（继承自 OrisonSpace）

- **全流程创作工作区** — 大纲、章节、人物与世界观资产卡一个工作区
- **本地优先** — 作品以普通文件保存在你自己的电脑上，无需账号
- **图片生成 + 编辑** — 文生图、图编辑（画笔/遮罩/裁切），结果直接入库
- **版本管理** — 基于 isomorphic-git 的提交节点、分支、diff 与时间线
- **IDE 式编辑器** — 分屏、Minimap、多标签、命令面板
- **模型自由** — 接入任何 OpenAI 兼容端点，密钥仅本地加密保存

> **实验性功能：** Agent Orchestration（多步编排）、Auto Mode（自动推进）、视频生成目前为实验性，不保证稳定。

## 适合谁

- **有故事想讲、但缺时间或缺笔力的人** — 你有灵感、有脑洞、有判断力，只是没有时间精力、或者自认文笔不行。你出创意和拍板，Closure 出执行力和工程保障
- **质量优先的网文 / 长篇小说作者** — 需要把大纲、章节、人物设定长期沉淀在一个工作区，要的是 AI 像人类作者一样思考，而不是像 AI 一样猜下一个词
- **同人作者（敬请期待）** — 原作理解、锚点、防 OOC 的同人创作管线在路线图上，这是项目的初心之一
- **想用 AI 但不想交出主导权的创作者** — Closure 是创作工作台，不是一次性自动生成器：每一处 AI 改动都可预览、可控、可回退
- **重视隐私与数据自主的人** — 作品全部以本地文件保存，不上传云端，不需要登录账号；自带任意 OpenAI 兼容 API Key

**明确不服务：** 想输入一句话就出整篇小说、不在乎质量只在乎出量的用户——创意写作归根结底是人类的工作，这类需求用 Closure 只会互相失望。

### 已知限制

- **macOS 包未签名**：Alpha 阶段无 Apple 开发者证书，首次启动会被 Gatekeeper 拦截——右键 App 选「打开」，或对解压/挂载出的 `Closure.app` 执行 `xattr -cr /Applications/Closure.app` 后再启动。
- **macOS 自动更新不可用**：应用内自动更新在 macOS 要求构建经过签名（electron-updater 拒绝安装未签名构建）——签名落地前升级请手动下载新版安装包覆盖。
- **arm64 产物未做真机验证**：Windows / macOS / Linux 的 arm64 包为理论可用（原生模块的 arm64 预编译均已在位），但我们手上没有 arm64 实机——遇到问题请[提 Issue](../../issues) 附平台与机型信息。
- **Linux 首选 AppImage**：免安装、无发行版包管理器耦合；deb/rpm 等格式暂未提供。
- **CI 已覆盖三平台机械验证**：全仓测试与启动冒烟（Electron 拉起到首帧）在 Windows / macOS / Linux CI 逐平台运行；日常使用的功能实测重心仍在 Windows——其他平台遇到平台相关问题请[提 Issue](../../issues)。

## 常见问题

**Closure 是什么？**
一款开源、本地优先的 AI 小说创作 IDE，把大纲、章节、人物与世界观资产卡整合到一个工作区，提供 AI 生成、续写、润色、审阅与可控修改。

**它和 ChatGPT 这类聊天工具有什么不同？**
它是面向长篇创作的工作台，而不是一次性生成器。项目结构、版本时间线、资产库长期沉淀；AI 的每次修改都可预览、可控、可回退，用户始终主导创作。

**我的作品数据会上传到云端吗？**
不会。Closure 本地优先，作品以普通文件（`project.yaml`、`chapters/*.md` 等）保存在你自己的电脑上，无需登录账号，数据不离开本地。

**支持哪些 AI 模型？**
任意 OpenAI / Anthropic 兼容端点；也可经 Antigravity CLI 直连调用 Gemini 系列模型。你用自己的 API Key 接入，自由选择文本与图片生成模型，密钥仅加密保存在本地。

**支持哪些操作系统？**
Windows、macOS（Intel 与 Apple Silicon）和 Linux。

**收费吗？开源吗？**
完全开源，采用 AGPL-3.0-or-later 许可证（源自 OrisonSpace 的代码保留 Apache-2.0），可免费使用。你只需自备模型 API 调用额度。

### 原生模块与 ABI

项目依赖 better-sqlite3 原生模块，它必须针对**当前运行时**编译：运行应用（`pnpm dev`）需要 Electron 的 ABI，运行测试（`pnpm test`）需要 Node 的 ABI——两者互斥，切换用途或切换 Node 版本后必须重编：

```bash
pnpm rebuild:native              # 按 Electron ABI 重建（运行应用 / pnpm dev 之前）
pnpm rebuild -r better-sqlite3   # 按 Node ABI 重建（运行测试之前；CI 会自动执行）
```

- 切换 Node 版本后，先按目标用途重编，再跑对应命令。
- 测试输出里数据库相关套件**整族 skip** 是 ABI 不匹配的信号（不是测试坏了）——先重编再排查。
